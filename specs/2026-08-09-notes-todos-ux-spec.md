## 1. 背景与目标

Edge Drop 当前以“快速捕获、检索、复制或粘贴剪贴板内容”为核心。笔记录与待办应当把短期剪贴内容沉淀为长期记录，同时保持剪贴板主流程的速度与清晰度。

本功能需要做到：

1. 用户可以独立创建笔记和待办。
2. 用户可以把剪贴板条目一键转成笔记或待办。
3. 已转换的记录不受剪贴板历史上限、自动清理、无痕模式和“清空剪贴板”影响。
4. 窄侧栏中不堆叠过多同级导航。
5. 中文界面、字体清晰度、减少动态效果和现有微互动风格保持一致。

## 2. 产品原则

### 2.1 剪贴板仍是主入口

- 首次安装默认进入“剪贴板”。
- 用户主动切换到“记录”后，普通面板关闭和重新打开保留上次工作区。
- 应用重启后恢复上次工作区；若状态无效则回退到“剪贴板”。
- 搜索词、临时展开状态和未提交的快速输入不跨面板关闭保留。

### 2.2 记录与剪贴板生命周期分离

- 清空剪贴板不能删除笔记或待办。
- 剪贴板自动删除不能删除记录。
- 删除记录不能反向删除原剪贴板条目。
- “无痕模式”只停止自动捕获剪贴板，不阻止用户手动创建或转换记录。

### 2.3 快速完成，逐步展开

- 常用操作直接可见：切换、搜索、新建、完成。
- 截止日期、附件状态、完整正文等次要信息按需展开。
- MVP 不引入文件夹、标签系统、富文本工具栏或完整日历。

## 3. 信息架构

### 3.1 一级导航

顶部使用双选分段控件：

- 剪贴板
- 记录

该控件属于工作区切换，不与内容筛选混排。

### 3.2 二级导航

剪贴板工作区保持现有筛选：

- 全部
- 文本
- 链接
- 图片
- 文件

记录工作区使用：

- 笔记
- 待办

右侧显示与当前记录页面对应的“新建”按钮。

### 3.3 搜索

- 搜索按钮默认只占一个图标位置。
- 点击后使用 Expanding Search 展开输入框，不挤压主导航。
- 搜索范围限定为当前页面：剪贴板、笔记或待办。
- 切换页面时清空搜索词，避免隐藏新页面中的内容。
- 笔记搜索标题、正文和附件名称；待办搜索标题、详情和附件名称。

## 4. 核心用户流程

### 4.1 剪贴板转为笔记

1. 用户悬停或选中剪贴板卡片。
2. 卡片动作区显示“保存为笔记”和“添加为待办”。
3. 用户选择“保存为笔记”。
4. 主进程根据剪贴板类型生成独立记录快照。
5. 成功后显示“已保存为笔记 · 撤销”。
6. 用户留在剪贴板页面；不自动跳转，避免打断连续处理。
7. 用户点击 Toast 中的“查看”时才进入对应笔记并打开编辑器。
8. 转换请求进行中时禁用该动作，防止双击产生重复记录。

说明：原型中为了展示功能会自动切换页面；正式实现采用“留在原地 + 查看入口”，减少上下文跳转。

### 4.2 剪贴板转为待办

流程与笔记相同。成功 Toast 为“已添加为待办 · 撤销 · 查看”。待办默认状态为未完成，默认无截止日期。

同一个剪贴板条目可以分别生成一条笔记和一条待办。若对应类型的来源记录仍存在，卡片动作显示“查看笔记”或“查看待办”，而不是再次创建重复记录；用户删除对应记录后，动作恢复为创建状态。

### 4.3 独立创建笔记

1. 进入“记录 > 笔记”。
2. 点击“新建”后在列表顶部展开快速输入。
3. 用户输入内容并保存，或直接进入完整编辑器。
4. 新笔记插入列表顶部并短暂闪现状态反馈。
5. 编辑器对标题和正文自动保存。

快速输入为空时不能提交；按 `Esc` 收起输入框。

### 4.4 独立创建待办

1. 进入“记录 > 待办”。
2. 点击“新建”后在列表顶部展开单行输入。
3. `Enter` 创建，`Shift+Enter` 不适用；详情在创建后按需编辑。
4. 新待办加入“今天”或“无日期”分组，并显示创建反馈。

### 4.5 完成与恢复待办

- 点击复选框立即乐观更新。
- 完成动画结束后将条目移动到“已完成”区域。
- 已完成区域默认折叠；本次会话中用户展开后保持展开。
- 恢复待办后回到其截止日期对应分组。
- IPC 失败时恢复原状态，并显示明确错误提示。

### 4.6 编辑笔记

- 点击笔记卡片打开同一面板内的全高编辑器。
- 编辑器包含返回、标题、正文、自动保存状态和最后编辑时间。
- 输入后 600ms 防抖保存。
- 关闭编辑器或关闭面板时立即刷新尚未落盘的修改。
- 保存失败时保留本地输入，显示“保存失败，正在重试”，不得静默丢失内容。

## 5. 内容转换规则

### 5.1 文本

转为笔记：

- 第一条非空行作为标题，最多 60 个字符。
- 完整文本作为正文。
- 标题截断只影响显示标题，不裁剪正文。

转为待办：

- 第一条非空行作为标题，最多 80 个字符。
- 剩余内容放入详情。

### 5.2 链接

- URL 作为标题或正文主体。
- MVP 不联网抓取网页标题、图标或摘要，避免转换变慢和隐私外发。
- 记录保留可点击链接能力。

### 5.3 图片与图片集合

- 转换时复制图片文件到记录专用资源目录。
- 记录资源使用新 ID，与剪贴板图片文件分离。
- 清理剪贴板图片后，记录预览和原图仍可访问。
- 转为待办时自动标题为“查看图片”或“处理 N 张图片”，用户可编辑。

### 5.4 文件

- MVP 保存文件路径、名称、扩展名、大小和转换时存在状态，不复制任意文件内容。
- UI 明确标记为“引用原文件”。
- 原文件移动或删除后显示“原文件不可用”，记录本身仍保留。
- 转为待办时自动标题为“处理：文件名”或“处理 N 个文件”。
- 后续版本可增加用户主动选择的“复制到记录中”，本期不做，避免不可控磁盘占用。

## 6. 数据模型

### 6.1 公共字段

```ts
type RecordAttachment =
  | {
      kind: 'image'
      assetId: string
      width: number
      height: number
      bytes: number
      ext?: string
    }
  | {
      kind: 'file-reference'
      path: string
      name: string
      ext: string
      size: number
      existedAtCreation: boolean
    }

interface RecordOrigin {
  kind: 'manual' | 'clipboard'
  clipboardItemId?: string
  clipboardKind?: ItemKind
  capturedAt?: number
}
```

`clipboardItemId` 只用于追踪来源，不建立生命周期依赖。原条目不存在时记录仍然有效。

### 6.2 笔记

```ts
interface NoteRecord {
  id: string
  title: string
  body: string
  attachments: RecordAttachment[]
  pinned: boolean
  createdAt: number
  updatedAt: number
  origin: RecordOrigin
}
```

### 6.3 待办

```ts
interface TodoRecord {
  id: string
  title: string
  details: string
  attachments: RecordAttachment[]
  status: 'pending' | 'completed'
  dueAt?: number
  completedAt?: number
  createdAt: number
  updatedAt: number
  origin: RecordOrigin
}
```

MVP 不包含优先级、重复规则、提醒通知和子任务。

## 7. 排序与分组

### 7.1 笔记

1. 已置顶，按 `updatedAt` 降序。
2. 未置顶，按 `updatedAt` 降序。

置顶区使用 Accordion，折叠状态按设备本地保存。

### 7.2 待办

未完成待办按以下顺序分组：

1. 已逾期
2. 今天
3. 即将到来
4. 无日期

同一分组中按 `dueAt` 升序，再按 `createdAt` 降序。已完成项目按 `completedAt` 降序。

“已逾期”仅使用文字和图标强调，不依赖高饱和红色，以保持项目当前的无彩色视觉语言。

## 8. 持久化与安全

### 8.1 存储结构

- 新建主进程 `RecordStore`，不把记录塞入 `ItemStore`。
- 索引文件：`records.json`。
- 图片资源目录：`record-assets`。
- `records.json` 使用与现有剪贴板索引相同的 Electron `safeStorage` 加密封装。
- 文件包含 `schemaVersion`，首版为 `1`。

### 8.2 写入策略

- 所有修改由主进程落盘，Renderer 不直接访问文件系统。
- 每次写入使用“临时文件 + 原子替换”，降低崩溃时产生半截 JSON 的概率。
- 加载失败时保留损坏文件副本，不用空数据覆盖原文件。
- 删除包含图片附件的记录时同步删除其专用资源。

### 8.3 边界

- 记录不参与剪贴板历史上限。
- 记录不参与自动删除小时数设置。
- “清除未置顶剪贴板”不影响记录。
- 本期不做云同步、账号体系或跨设备同步。

## 9. IPC 与状态边界

### 9.1 主进程为数据真相源

Renderer 可以乐观更新，但主进程结果始终具有最终权威。

建议新增类型化 IPC：

```ts
'records:load'
'records:convert-clipboard'
'note:create'
'note:update'
'note:set-pinned'
'note:delete'
'todo:create'
'todo:update'
'todo:set-completed'
'todo:delete'
'todo:clear-completed'
```

新增主进程推送事件：

```ts
'state:records'
```

转换接口由主进程接收剪贴板条目 ID，再读取真实 `ItemStore` 数据生成快照，Renderer 不上传可伪造的本地路径或图片资源路径。

### 9.2 Renderer 状态

- 新建独立的 Zustand `recordStore` 管理笔记、待办、加载和保存状态。
- 现有 `appStore` 只增加工作区、记录子页面和编辑器等 UI 状态。
- 不把记录数组继续堆入现有 `appStore`，避免剪贴板更新触发所有记录组件重渲染。

## 11. Interior 微互动映射

| 位置 | 组件模式 | 行为要求 |
| --- | --- | --- |
| 工作区和记录切换 | Segmented Control | 单一滑块、可中断、无布局跳动 |
| 搜索 | Expanding Search | 向可用空间展开，关闭后清空当前查询 |
| 新建与卡片动作 | Press Depth | 轻微位移或缩放，不长期提升 GPU 图层 |
| 转换、创建、完成 | Ripple / Value Flash | 短暂反馈，不改变布局尺寸 |
| 长笔记 | Show More | 动画高度，正文宽度保持不变 |
| 置顶和已完成区域 | Accordion | 高度可中断，减少动态时立即切换 |
| 待办完成 | Icon Morph | 方框到勾选状态，状态仍有文字/样式辅助 |
| 清理完成项 | Hold to Confirm | 按住显示进度，放开未完成则取消 |
| 新记录到达且列表未置顶 | New Items Pill | 点击回到顶部，不强制滚动 |

动效不得加入长期 `will-change`、静态 `translateZ(0)` 或 `backface-visibility`。Framer 只在运动期管理合成层。

## 13. 错误与撤销

- 转换失败：保留原剪贴板内容，显示“保存失败，请重试”。
- 图片资源复制失败：不创建残缺记录；已经复制的临时资源回滚。
- 文件引用失效：记录仍可编辑和删除，附件显示不可用状态。
- 自动保存失败：编辑器内容不清空，后台有限重试并提供再次保存入口。
- 单条删除采用立即删除 + 5 秒撤销 Toast。
- 转换成功后的撤销只删除新建记录，不影响原剪贴板条目。
- 批量清理已完成待办使用 Hold to Confirm，完成后仍提供短时撤销。
- 为保证包含图片附件的记录可撤销，主进程先把删除项放入短期 tombstone；撤销窗口结束后才最终删除图片资源。

## 14. 键盘与无障碍

- `Ctrl+F`：展开并聚焦当前页面搜索。
- 记录页面 `Ctrl+N`：打开当前类型的新建入口。
- `Esc`：依次关闭搜索、快速输入、编辑器。
- 待办输入 `Enter`：创建。
- 笔记编辑器 `Ctrl+S`：立即刷新保存，并显示已保存状态；自动保存仍默认开启。
- 所有图标按钮必须有中文 `aria-label` 和 Tooltip。
- 复选框使用真实按钮语义并暴露 `aria-pressed` 或等效状态。
- 键盘焦点不能被动画卸载后丢失。
- 文字与背景对比度不低于现有界面基线。

## 15. 响应式与面板约束

- 按当前约 300px 窄面板作为主要设计基线。
- 字体缩放 0.85、1.0、1.15 下不得截断一级导航。
- 搜索展开时可暂时隐藏次要设置图标，但不能挤压分段控件文字。
- 编辑器使用面板内部全高视图，不扩大主窗口宽度。
- 预览 Flyout 与记录编辑器不能同时打开。

## 17. 验收标准

### 数据与生命周期

- 清空全部剪贴板后，所有笔记和待办仍存在。
- 达到剪贴板历史上限并淘汰来源条目后，记录仍存在。
- 重启应用后记录、完成状态、截止日期和置顶状态正确恢复。
- 图片转换后删除来源剪贴板条目，记录图片仍能完整查看。
- 文件源不存在时显示不可用状态，不导致记录页面崩溃。

### 交互

- 一级和二级导航在 0.85、1.0、1.15 字体缩放下不重叠。
- 转换成功不强制跳离剪贴板页面。
- 新建、转换、完成、恢复和删除均有明确反馈。
- 自动保存过程中关闭编辑器不会丢失最后一次输入。
- 已完成区域展开或折叠不会造成正文横向重排。
- 开启减少动态效果后，全部状态变化仍可被识别。

### 质量

- TypeScript 类型检查通过。
- Vitest 现有测试全部通过。
- 新增 RecordStore、转换规则、IPC 和主要 UI 行为测试通过。
- `electron-vite` 生产构建通过。
- Windows 100%、125%、150% DPI 下完成视觉检查，中文字体无新增模糊。
- 长列表中不存在每卡片长期 `will-change` 合成层。

## 18. 实施前必须锁定的决定

本规格建议锁定以下选择：

1. 正式转换后留在剪贴板，用 Toast 提供“查看”，不自动跳转。
2. 图片复制进记录资源目录；普通文件只保存引用。
3. MVP 不加入提醒、重复、优先级、标签和富文本。
4. 记录使用独立 `RecordStore`、独立加密索引和独立 Zustand store。
5. 使用现有 `framer-motion` 适配 Interior 微互动，不增加第二套动画运行库。

用户确认本规格后，再编写逐文件实施计划并开始修改正式代码。
